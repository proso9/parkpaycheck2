# 停车场异常车辆检测工具

从停车场系统日志中找出**「出场不开闸」且判定窗口内（默认 300 秒）无支付结果下发**的异常车辆，导出 CSV，并可自动上传到 Cloudflare D1 数据库供其他系统展示。

核心检测与数据库上传**零第三方依赖**；图形界面的定时任务与系统托盘需要 3 个第三方库。

## 功能特性

- **核心检测**（无第三方依赖）：解析系统日志，定位「出场不开闸」且窗口期无同车支付下发的车辆，并反查入场时间、关联用户需支付费用。
- **可疑标记**：对比系统「停车时间」与「入场→出场」实际时长，明显超出的车辆（如门卫遥控放行）额外标记为可疑。
- **排除已处理日志**：内容未变化的已处理日志自动跳过，定时任务不会重复处理旧日志；当天仍在写入的日志会正常重新检测。
- **数据库上传（Cloudflare D1）**：异常记录自动上传到 D1（仅标准库实现，直接调 D1 REST API）；`INSERT OR IGNORE` + 去重键幂等，只插入新记录、永不覆盖；上传成功才标记日志已处理，失败自动留待下轮重试。
- **图形界面（GUI）**：基于 tkinter，五个配置页签（路径配置 / 判定参数 / 定时任务 / 数据库上传 / 运行输出），配置可导入导出 JSON（API Token 绝不导出）。
- **定时任务**：基于 APScheduler，间隔运行或每天固定时间，修改配置无需重启即生效。
- **系统托盘**：关闭窗口自动收纳到托盘，后台定时任务继续运行。
- **静默启动**：附 `start_gui.vbs`，以 `pythonw` 拉起 GUI，无命令行黑窗口，可配置开机自启。

## 快速开始

### 环境要求与安装

- Windows 10 / 11，Python 3.8+

```powershell
# 核心检测与数据库上传无需任何第三方依赖，命令行可直接运行
# 图形界面（定时任务 + 系统托盘）需要安装以下依赖：
python -m pip install apscheduler pystray Pillow
```

| 依赖 | 用途 |
| ---- | ---- |
| `apscheduler` | 定时任务调度（间隔运行 / 每天固定时间） |
| `pystray` | 系统托盘图标（关闭窗口后收纳右下角） |
| `Pillow` | 生成托盘图标图像 |

### 30 秒上手

```powershell
# 处理 document/ 下所有日志，结果输出到 output/
python check_unopened_gate.py

# 或启动图形界面
python check_gui.py
```

结果写入 `output/异常车辆_<日志日期>.csv`，内容见 [输出说明](#输出说明)。

## 使用指南

### 命令行

```powershell
# 处理 document/ 下所有日志，默认输出到 output/
python check_unopened_gate.py

# 指定单个日志
python check_unopened_gate.py document\system.2026-08-22.log

# 调整判定窗口(秒)与输出目录
python check_unopened_gate.py -w 300 -o output

# 忽略已处理记录，强制重新处理所有日志
python check_unopened_gate.py --reprocess

# 开启数据库上传（也可经 .env 配置，见下文）
python check_unopened_gate.py --upload --cf-account <账户ID> --cf-database <库ID> --cf-token <API_Token>

# 也可通过模块方式运行
python -m parkcheck.cli -w 300 -o output
```

| 参数 | 说明 | 默认值 |
| ---- | ---- | ------ |
| `log`（位置参数） | 日志文件或目录 | `document` |
| `-w, --window` | 判定窗口秒数 | `300` |
| `-o, --out` | CSV 导出目录 | `output` |
| `--reprocess` | 忽略已处理记录，强制重跑 | 关闭 |
| `--upload` | 启用数据库上传 | 关闭 |
| `--cf-account` | Cloudflare Account ID | 空 |
| `--cf-database` | D1 Database UUID | 空 |
| `--cf-token` | Cloudflare API Token（`D1:Edit` 权限） | 空 |
| `--db-batch` | 单次上传请求最多合并的记录数 | `50` |

### 静默启动与开机自启（无命令行黑窗口）

直接 `python check_gui.py` 会先弹出一个命令行黑窗口。项目根目录提供了静默启动脚本 **`start_gui.vbs`**（已实测）：

- **日常启动**：双击 `start_gui.vbs`，GUI 以 `pythonw.exe`（无控制台版 Python）静默拉起，只有主窗口、没有黑窗口。
- **开机自启**：`Win+R` 输入 `shell:startup` 回车，把 `start_gui.vbs` 的快捷方式放进去。开机自动后台拉起 GUI，配合 `.env` 里的上传配置与 GUI 里的定时任务、系统托盘，即可全程无人值守运行。

脚本说明：自动探测常见安装位置的 `pythonw.exe`（官方安装器与微软商店版均覆盖，找不到时退回 PATH 解析）；以脚本所在目录为工作目录，存放到任意位置均可用。注意：该脚本含中文注释，请以 **ANSI/GBK** 编码保存（当前文件已是），用记事本另存时编码选「ANSI」即可，存成 UTF-8 会导致解析错误。

## 配置说明

### 配置来源与优先级

上传相关 5 项配置（上传开关、账户 ID、数据库 ID、API Token、批量大小）支持三级来源，优先级从高到低：

```
显式命令行参数 > 环境变量（含项目根目录 .env）> config.py 默认值
```

### 本地密钥持久化（.env）

把 `.env.example` 复制为项目根目录下的 `.env` 并填写，GUI 的「数据库上传」页签会自动带出初始值（重启免手填）：

```ini
UPLOAD_ENABLED=1
CF_ACCOUNT_ID=<账户ID>
CF_DATABASE_ID=<库ID>
CF_API_TOKEN=<API_Token>
DB_BATCH_SIZE=50
```

`.env` 已加入 `.gitignore`，**不入仓库**；`parkcheck/env.py` 仅用标准库解析（支持 `#` 注释、引号包裹、`export` 前缀），已存在的系统环境变量不会被 `.env` 覆盖。API Token 无论来源，均不随 GUI「导出配置」JSON 导出。

### 数据库上传（Cloudflare D1）

- **表自动创建**：首次上传前自动执行 `CREATE TABLE IF NOT EXISTS anomalies`（幂等），无需手动初始化。
- **只插入新记录，永不覆盖**：`INSERT OR IGNORE` + 唯一去重键 `sha256("{日志文件名}|{全格式出场时间}|{车牌}")`；本工具对已有记录不做任何 UPDATE，处理状态（status）/备注（remark）由展示项目人工维护。
- **上传成功才标记已处理**：上传开启时流程为 检测 → 输出 CSV → 上传 D1 → 标记已处理；上传失败（网络 / Token / 库 ID 错误）打印明确错误、该日志不标记，下一轮自动重试（去重键兜底，不产生重复）。关闭上传时行为与无上传版本完全一致；三项凭证任一为空视为未配置上传（等同关闭，提示一次）。

## 输出说明

### CSV 结果

写入 `output/`，命名 `异常车辆_<日志日期>.csv`（如处理 `system.2026-08-22.log` 生成 `异常车辆_2026-08-22.csv`）：

| 列 | 说明 |
| -- | ---- |
| 入场时间 | 反查到的最近一次入场时间，找不到显示 `-` |
| 出场时间 | 出场不开闸记录的时间 |
| 车牌号 | 归一化（去空格、转大写）后的车牌 |
| 用户需支付费用 | 关联的应付费用，无关联显示 `-` |
| 异常 | `1` 表示系统停车时间明显大于实际时长（可疑，如门卫遥控放行），否则 `0` |

### 已处理日志状态

状态记录在 `output/.processed.json`（按文件大小 + 修改时间判断），内容未变化的日志再次运行时自动跳过；删除该文件或使用 `--reprocess`（GUI 取消勾选）即可全部重新处理。

### D1 数据表 anomalies

| 字段 | 说明 |
| ---- | ---- |
| `log_date` / `log_file` | 来源日志日期 / 文件名（取自文件名） |
| `entry_time` / `exit_time` | 入场 / 出场时间，全格式 `YYYY-MM-DD HH:MM:SS`（日志内只有时刻，用文件名日期补全）；入场缺失为 `NULL` |
| `car_number` | 归一化车牌 |
| `fee` | 应付费用（REAL），无关联为 `NULL` |
| `is_suspicious` | 可疑标记，同 CSV「异常」列 |
| `dedup_key` | 去重键（UNIQUE，幂等核心） |
| `status` / `remark` | 处理状态（0 未处理 / 1 已处理 / 2 误报）与备注，**由展示项目维护，本工具只写默认值** |

## 工作原理

检测流程：

1. 解析含「出场处理」且「开闸结果：不开闸」的行，得到出场时间 `T` 与车牌（部分业务行不带时间戳，继承上一条带时间戳行的时刻）。
2. 解析含「==>支付结果下发：」的行，得到支付下发的车牌与时间（`carNumber` 优先 JSON 解析，失败正则兜底）。
3. 对每条「不开闸」记录，在支付下发中查找**车牌相同且时间在 `[T, T+300 秒]` 窗口内**的记录；找不到且能取到应付费用则判为异常。
4. 反查最近一次入场时间：以相机「方向：入口」扫描为准（5 秒内重复扫描归并为同一次入场），「入场车牌号」行兜底；找不到显示 `-`。
5. 对比系统「停车时间」与实际「入场→出场」时长，明显超出（至少多出 `MIN_PARK_TIME_DEVIATION` 分钟）的标记可疑。

上传流程（开启时）：

6. 以去重键把异常记录经 D1 REST API `INSERT OR IGNORE` 写入 `anomalies` 表（按 `DB_BATCH_SIZE` 分批，参数化防注入）。
7. 上传成功才把该日志写入 `.processed.json`；失败不标记，下一轮（含定时触发）自动重试。

## 注意事项

- 输出结果写入 `output/`，**不要**写入 `document/`；两者与 `tests/` 均已加入 `.gitignore`。
- 日志为 `system.<YYYY-MM-DD>.log` 命名，输出 CSV 用同日期命名。
- **API Token 等涉密信息不得写入代码、配置文件或「导出配置」JSON**；本地持久化用 `.env`（不入仓库）。
- 修改判定逻辑后请运行本地测试（`tests/` 目录，不入仓库）并确保全部通过。
